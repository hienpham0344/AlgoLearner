Standalone trusted Linux worker. The API only writes PostgreSQL jobs; `JudgeWorkerMain` is never registered as a Spring bean.

Build backend with Java 21. Resolve its existing runtime dependencies and set `JUDGE_CLASSPATH` to `target/classes` and those jars. Run `bash backend/judge-worker/run.sh` as a separate trusted service with Docker access. API service users must not have Docker/socket access.

Required worker environment: `JUDGE_DB_URL`, `JUDGE_DB_USERNAME`, `JUDGE_DB_PASSWORD`, `JUDGE_WORK_DIR` (absolute, private local directory), `JUDGE_JAVA_IMAGE`, `JUDGE_PYTHON_IMAGE`. Images must be preloaded references containing `@sha256:` plus 64 lowercase hex digits. Use Java 21 JDK and Python 3.12 images providing `javac`, `java`, or `python3`; tags and runtime pulls are rejected. Supply credentials through service configuration, never learner mounts or CLI arguments.

Provision a dedicated worker database role on staging. The runtime needs to read/lease/update `tbl_judge_job` and delete expired RUN jobs; its grants and RLS policies must permit those operations. Restrict writable columns to job status/result/lease/retry metadata, and scope deletion to RUN. Schema ownership, account tables, Storage credentials and SMTP credentials belong to the API/operator context. Verify the role against the actual schema before rollout; application migrations currently revoke browser roles and do not provision this deployment-specific worker login.

The compiler runs inside an isolated container with `javac -proc:none`; artifacts use a bounded 32 MiB Docker tmpfs volume. Every testcase uses a fresh runtime container, read-only artifacts, network disabled, memory 256 MiB, one CPU, PID limit 32, dropped capabilities, read-only root, unprivileged UID and no-new-privileges. Only source is bind mounted. Expected outputs remain in worker memory/database. Stdout/stderr drain concurrently with 64 KiB maximum retained each. Compiler deadline <=10 seconds, case deadline <=5 seconds (default caller limit 2 seconds). Container cleanup failure is an infrastructure error. Jobs retry at most three leases; stale tokens/generations cannot overwrite results.

Contract: trusted modules authorize resources before calling `JudgeGateway`; there is intentionally no public endpoint accepting testcase snapshots. RUN filters sample cases, has an atomic rolling five-per-minute quota, and creates no official submission. SUBMIT atomically stores immutable source/testcase snapshots and its job. Comparator is `TOKEN_WHITESPACE_V1` (case-sensitive). Hidden input/output is returned only for `FULL_DETAILS` with explicit `allowDetails`; PASS_FAIL returns no testcase records.

Real Docker execution must be verified on a Docker-equipped Linux worker before release. Unit/SQL tests do not establish container isolation at runtime. The worker removes non-running temporary RUN jobs older than 24 hours. Official submissions and their jobs remain immutable/auditable.

Runtime stdin stays open with `--interactive` (without TTY), so testcase input reaches the learner process. Containers remain until their exit state is inspected; exit 137 is MLE only when Docker reports `State.OOMKilled=true`, otherwise it is a runtime error. Each path explicitly removes the container; volume cleanup and local source cleanup are independent. An inspection or cleanup failure remains an infrastructure failure and does not publish a learner verdict.
