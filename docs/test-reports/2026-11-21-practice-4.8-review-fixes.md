## Notes for reviewers

- The practice migration is now `V202611210001__init_classroom_practice.sql`. It was renumbered because `main` already has migrations up to `V202611180014`; Flyway rejects a lower, not-yet-applied version on any database that ran `main`. It also enables RLS on its four tables, like every other module. A database that applied the earlier `V202611150001` file must be recreated.
- `main` already contains a separate class-practice implementation (`ClassPracticeController`/`ClassPracticeService`, table `tbl_class_practice`, routes under `/classrooms/{id}/practice`). Ours lives under `/classrooms/{id}/practices` with `tbl_classroom_practice`; they do not collide technically, but the team should decide which one is the 4.8 implementation going forward.
- `ON CONFLICT DO NOTHING` is used without a conflict target: it is valid PostgreSQL and the only form H2's PostgreSQL mode parses. The table has a single unique key (the primary key), so the behaviour is identical.
- `LessonStatusPort` gained `archivedLessonIds(classroomId)`; module 4.5's adapter must implement it. `PracticeJudgePort.SubmitResult` gained `testsPassed`; the 4.9 adapter must supply it (0..number of testcases, equal to it when ACCEPTED).
- Admin access (open question, answered): an ACTIVE Admin may now read practices (list, detail with sample testcases only), progress, class submissions and single submissions of any classroom. Running, submitting, every write, own-submission history and the hidden-testcase listing stay 403 for Admin. Covered by `PracticeApiTest.adminIsReadOnly` and `PracticeServiceTest.adminIsReadOnly`.
